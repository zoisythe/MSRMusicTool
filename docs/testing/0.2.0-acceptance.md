## 复现

```powershell
$env:MSR_ARIA2_BINARY = '本机 aria2c.exe 的绝对路径'
$env:MSR_ARIA_NEXT_BINARY = '本机 aria2-next.exe 的绝对路径'
$env:MSR_RUN_LIVE_TESTS = '1'
uv run --no-sync pytest -q --junitxml=build/acceptance-tests.xml

uv build
uv run --no-sync python scripts/build_standalone.py
uv run --no-sync python scripts/verify_standalone.py --live --report build/standalone-acceptance.json
uv run --no-sync python scripts/verify_standalone.py --live --wheel dist/msrmusictool-0.2.0-py3-none-any.whl --report build/wheel-acceptance.json
```

兼容性回归使用 `uv run --python 3.11 --isolated --locked --group dev pytest`，没有设置
`MSR_RUN_LIVE_TESTS`，因此该轮跳过官网契约项；官网契约在 Python 3.14 轮次执行通过。

WSL 在 Linux 文件系统的独立目录中复制当前源码，使用 Linux 虚拟环境和构建缓存。
验证前确认了 32 个源码、配置及测试文件的 SHA-256 与 Windows 工作区一致。
Aria2 从 Arch 官方签名软件包提取到验收目录；Aria2 Next 从官方 v2.8.3 Release 下载，
二进制 SHA-256 与官方校验文件一致。环境及引擎详情见
[Linux 环境报告](assets/0.2.0/linux-environment.json)。在该目录中执行：

```bash
export UV_NO_CONFIG=1 # 本机 uv 全局镜像与项目锁文件来源不同，仅验收进程禁用
export LD_LIBRARY_PATH="$PWD/build/engines/aria2/usr/lib" # 提取版 Aria2 的共享库
export MSR_ARIA2_BINARY="$PWD/build/engines/aria2/usr/bin/aria2c"
export MSR_ARIA_NEXT_BINARY="$PWD/build/engines/aria2-next"
export NO_PROXY='monster-siren.hypergryph.com,.hycdn.cn,127.0.0.1,localhost'
uv sync --locked --group dev --group standalone
MSR_RUN_LIVE_TESTS=1 uv run --locked --no-sync pytest -q --junitxml=build/linux-python314.xml
uv run --python 3.11 --isolated --locked --group dev pytest -q --junitxml=build/linux-python311.xml
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
uv build
uv run --no-sync python scripts/build_standalone.py
uv run --no-sync python scripts/verify_standalone.py --live --report build/linux-standalone.json
uv run --no-sync python scripts/verify_standalone.py --live --wheel dist/msrmusictool-0.2.0-py3-none-any.whl --report build/linux-wheel.json
```

## 边界与证据完整性

- Linux 已在 WSL2 Arch Linux 上执行；macOS 未在本机执行，CI 配置不能作为已通过的证据。
- Linux 独立程序使用 Arch 的 Python 3.14/glibc 2.44 构建；未验证它在较旧 glibc 发行版上的兼容性。
- RPC 验收使用本机目录及显式目录配置；没有验证跨操作系统 NAS 挂载。
- 较早的发布验收出现环境代理路径上的 TLS EOF 和官网接口请求失败；最终产物验收在
  执行进程中临时设置 `NO_PROXY=monster-siren.hypergryph.com,.hycdn.cn,127.0.0.1,localhost`
  后直连通过。程序仍继承环境代理，没有禁用 TLS 校验或修改用户配置。
- 没有推送版本标签或发布 GitHub Release。

[manifest.json](assets/0.2.0/manifest.json) 记录最终产物和引擎的 SHA-256，以及每份原始
证据与归档副本的 SHA-256；归档时逐项确认一致。这里只归档直接引用的报告，没有复制
完整构建目录或媒体验收目录。
归档文件通过 `.gitattributes` 禁用换行转换，并核对 Git 对象字节的 SHA-256，以确保
不同操作系统检出后仍能校验证据。
